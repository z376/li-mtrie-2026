## §2 第 2 条 — 表面边界行过能量守恒 + 独立换实现复算

### 2.1 为什么这条是 P0-1 的"决定性证据"

2026A v15 的温度场 `build_surface_row` 返回 `(1.0, 1+beta, beta)`, `beta = h·Δr/α` **无 Δt**,
等价于 h→∞ 极限——表面被错误地钉死在 T_amb（题面给的是有限 h=25）。

| 实现 | 边界行 | `dE/dt ÷ [h(T∞−Ts)·A]` |
|---|---|---|
| 错 (P0-1) | `(1.0, 1+β, β)` | **223** (不可能的 223 倍) |
| 对 (真 Robin) | `(1+2μ+γ, −2μ, γ)`, γ = 2·h·Δt/Δr | **0.995** |

求解照样收敛、曲线照样漂亮、图照样好看——**只有守恒比值能揭穿它**.

### 2.2 怎么用 (3 步)

```powershell
# 1) 求解时接入 2 行 (mechanism-template.py § 4.1 有完整片段)
#    rec.record(t, E_total, flux_boundary)   # 循环内每步
#    rec.save('结果/守恒记录.csv')

# 2) 跑完出报告 (ratio 偏离 1 > 0.05 → 离散式几乎必错)
py -3 references/scripts/bc_check.py --csv 求解/问题1/结果/守恒记录.csv

# 3) dryrun 自动扫 (check 64)
py -3 references/scripts/dryrun.py --mode self
```

物理量约定: `E_total` = 系统总内能 (J); `flux_boundary` = 边界净通量 (W), **流入为正**, 与 dE/dt 同号。

### 2.3 "独立换实现复算"记录 (第 2 条后半句)

守恒校验只能证伪**单点错误**, 证不了"整个模型错了但自洽"。所以代理审计 A2 板块要求
**自写另一套求解器** (scipy banded 或另一套 FVM) 复现 ≥1 个关键结果, 相对误差 <0.5% 才算一致.
复算过程与偏差写进 `求解/审计报告*.md` 的 A 板块结论 (格式见 `references/代理审计prompt.md` §3.1).

> **不要信任自己的代码**——2026A 复盘原文: "自己的'自洽'可能是错的" (P0-1 就是自洽的错).

## §3 第 3 条 — 论文数字全部可溯源, 关键判据二次复算

### 3.1 三类可信来源 (缺一即 red)

1. **脚本 print / 结果文件读** — `resultX.xlsx`、`.csv` 里读出来
2. **公式现场算** — 论文里给出公式与代入值
3. **台账登记** — `references/audit/数值台账规范.md` + `references/scripts/number_ledger.py`

**反例** (2026A v15 P0-3): Bi_m 心算 32, 实际 3.24, 差 10 倍, 论文里两个数都用了.

### 3.2 自动检查

| check | 检查什么 | 判据 |
|---|---|---|
| **55** | Bi/Fo/收缩率/Re/Pr 等关键判据是否带来源标记 | 含实算/print/resultX/公式 → green; 无来源 → yellow |
| **40** | 论文数字 vs result 文件 (按问题编号配对) | 偏差 >5% red / 1-5% yellow / <1% green |
| **65** | 论文正文数字的**台账覆盖率** (反向: 论文里有、但台账里查不到) | 台账不存在 yellow / 台账 <3 条 yellow / 覆盖率 <40% red / 40-70% yellow / ≥70% green |

> check 40 是**正向** (result 里的数是否出现在论文), check 65 是**反向** (论文里的数是否有出处).
> 两个方向都绿 = "全部可溯源".
>
> **check 65 的候选数字口径** (v1.6.4): 排除年份 1900-2100、排除 0-9 的整数计数 (如"3 个""5 折")、
> 排除注释与数学环境与 `\label/\ref` 内部; 其余 (含小数、≥10 的整数、百分数) 都要在台账里找得到.
> 台账来源列: 1=脚本 print / 2=resultX.xlsx / 3=公式现场算 / **4=题面给定** (v1.6.4 新增,
> 让题面常数也能被登记, 避免"常数没台账 → 误报未溯源").

### 3.3 二次复算

关键判据 (Bi / Fo / 收缩率) 必须在 `求解/审计报告*.md` 或过程日志里留**一次手算复算**记录,
写清代入的数与结果. 没有复算记录 = 判据来源只有一个 (脚本), 不满足验收标准.

## §4 第 4 条 — 图内无 figure 级 set_title + 论文表头含题面组表头

| check | 检查什么 | 判据 |
|---|---|---|
| **59** | fig_sanity 内容级: 顶部暗像素占比 > 0.06 (残留 set_title) | red / 恒定曲线 np.ptp=0 red / U+2080 乱码 yellow |
| **61** | 论文表格两行表头: `\multicolumn` (组标签) + `\multirow` (命名列) 配对 | 全无配对 red / 缺 `\multirow` yellow / 配对 green |

**根因**: 标题只能由 `\caption` 承担——图内再写一遍 = 双标题 (2026A 22 张图全中招).
规范见 `references/plot/绘图规范与避坑.md` §〇 第 0 条.

**题面组表头**指题面表 1-6 那种"到药材中心的距离/cm"跨列组标签,
论文里必须用 `\multicolumn{n}{c}{组标签}` + `\multirow{n}{*}{列名}` 复刻, 不能拍平成单行.

## §5 第 5 条 — 重跑后 P0-7 清单 6 项逐项打钩

**这不是自动检查, 是人工 6 项**——因为"旧值是否过期"取决于你刚改了哪一处, 没有静态特征可扫.
完整 6 项 + 4 段 PowerShell 命令在 `references/audit/验收清单.md` **§H**.

| # | 项 | 命中什么算翻车 |
|---|---|---|
| H1 | 重跑 `gen_tables.py` 重新生成表 | 论文表里还是旧值 |
| H2 | 手写数值表重填 (灵敏度/完整性/检验) | 手写表 ≠ 最新检验 CSV |
| H3 | 附录 verbatim 代码片段逐字一致 | 附录里还是改之前的代码/数字 |
| H4 | AI 使用详情 ↔ 论文对账 | 关键数字/边界叙事/小节编号对不上 |
| H5 | 历史过程日志加"历史版本·已被取代"头注 | 旧结论 (如已被推翻的 Dirichlet) 没标注 |
| H6 | 引用编号查 `.aux` | 引用编号与实际表/图号错位 |

## §6 第 6 条 — 代理审计报告存档 + 回执齐全

| 要求 | 落地 |
|---|---|
| 存档路径 | `求解/审计报告*.md` (代理审计 prompt §0 已固定) |
| 历史报告 | 带 **"历史版本·已被取代"** 头注 (G4 + H5 联动) |
| 修复回执 | 每个 P0 都要有"改了什么 + 复现值" (prompt §3.1 格式: P0 必给复现值, 不写"约 1.4") |
| 不缓存 | 每次审计用**独立 context** 的 worker, 不复用主对话历史 (prompt §5) |

> 其中第二轮抓出 2 个模型级错误——**自查永远查不出自洽的错**.
