# 数值台账规范 (v1.5.8.2 新增, P0-3 防御)

> **踩坑教训**: 2026A 复盘 v1.1 §0 (Sep 28 改进意见 P0-3) — 5.2.2 节 ρ/cp/k 起止值系**目视读图臆造** (实为 976.4→667.3 等); 5.4.1"前 10h→1.424cm、占 78%"**同为目测错** (实 5h、71.8%). 本轮新增: **连"手算的关键判据"也会错** — `Bi_m` 被算成 32 (实 3.24). 决定性证据: 评审找代理公式复算时全部暴露, 评"模型不严谨" 0 分.
>
> **本规范权威源**: 论文中所有数字 (除题面直接给出的) 必来自 3 类可信来源之一, **禁止凭图读数 + 禁止一次性心算**. 配套工具: `references/scripts/number_ledger.py` (数值台账生成 + 核对脚本).

## 1. 三来源约束 (论文数字只准以下 3 类来源)

| # | 来源 | 适用 | 例子 |
|---|------|------|------|
| 1 | **脚本 print 落盘** (求解日志) | 求解过程数字 (峰值温度/平衡水分/半干燥时间) | solver 输出的 `T_max=33.5279, t_dry=205906 s` |
| 2 | **从 resultX.xlsx / 表N.csv 程序读取** (gen_tables.py 做法) | 表格数字 (附表 1-6) | `pd.read_excel('result1.xlsx').iloc[:, 1].tolist()` |
| 3 | **论文写作现场用公式当场计算 + 关键判据二次独立复算** | 推导判据 (Bi/Fo/收缩率/Re/Pr) | `Bi = h·L/k = 25·0.02/0.5 = 1.0` (纸上演算) |

**禁止**:
- ❌ **凭图读数** (从数据图上"目测" 数值, 精度不够)
- ❌ **一次性心算** (不写公式直接说"约 1.4", 关键判据会算错 10 倍)
- ❌ **AI 写数字** (AI 可能编造, 关键判据 Bi_m=32 实 3.24)

## 2. 数值台账.csv (P0-3 强制)

**Step 3 起手必建** `求解/数值台账.csv`, 4 列结构:

| 列名 | 含义 | 例子 |
|------|------|------|
| `符号` | 论文 §4 符号说明的 latex 符号 | `\rho` |
| `值` | 实际数值 (含单位) | `976.4` (kg/m³) |
| `来源` | 1=脚本 print / 2=resultX.xlsx / 3=公式现场算 / **4=题面给定** | `1` |
| `生成脚本` | 来源对应的文件路径 | `求解/问题1/solve_1.py:L42 print` |

**约束**:
- 论文中**所有非题面数字** (除小整数 0/1/2/3 等约定) 都应**至少有一行台账**
- 关键判据 (Bi/Fo/收缩率/Re/Pr) 必须在 §4 符号说明同时**显示公式** + **台账来源**
- 跑题用户每写一段文字涉及数字 → 立即填一行台账, **不要等写完再补**
- **题面常数也登记** (来源 4, v1.6.4 新增): 题面给的 h=25 / R=5cm 这类数也进台账,
  否则 check 65 会判"查不到出处" → 题面常数确实**有出处** (出处就是题面), 登记后即通过

## 3. 跑前/跑后 4 道防线

### 3.1 Step 3 起手 (写 §1 引言前)
- 建 `求解/数值台账.csv` 文件 (空表, 4 列)
- 跑 `py -3 references/scripts/number_ledger.py init --root .` 生成空表 + 现有 result 扫描
  (⚠️ `--root` 是**必填**, 指向跑题根目录 = 含 `求解/` `论文/` `数据/` 的那层; 漏了会 argparse 报错 exit 2)

### 3.2 每章写完 (尤其 §5.X 建模求解)
- 每写一个数字 → 加台账行
- 关键判据 → 写公式 + 二次复算 (e.g. Bi, 不同单位组合验算)

### 3.3 Step 4.3 跑合规检查前
- 跑 `py -3 references/scripts/number_ledger.py check --root . --paper 论文` 自动 grep 论文数字
  (`--root` 必填 + `--paper` 指向论文目录; 退出码 0 = 匹配率 ≥70%, 1 = <70%)
- 报告: 论文中所有数字 vs 台账中值的匹配率, 未匹配的红

### 3.4 Step 4.5 最终提交前
- dryrun check 55 (L22, v1.5.8.2 新增) 自动扫关键判据来源标记
- dryrun check 65 (L31, v1.6.4 新增) 自动算**台账覆盖率** (反向: 论文里的数有没有出处)
- 必跑一遍, 红项立即修

## 5. dryrun check 65 (L31) 台账覆盖率 (v1.6.4 新增)

`references/scripts/dryrun.py` `check_number_ledger_coverage`:

- **反向**检查 (check 40 是正向: result 里的数是否出现在论文)
- 扫论文正文 .tex 提**候选数字**: 排除年份 1900-2100、排除 0-9 的整数计数、排除注释/数学环境/`\label`/`\ref`
- 覆盖率 = 台账命中的唯一数字 / 论文候选唯一数字
- 判据: 台账不存在 yellow / 台账 <3 条 yellow / 覆盖率 <40% **red** / 40-70% yellow / ≥70% green
- red 含义: **多数数字无可溯源来源** = P0-3 "目测数字"风险复发, 必须补台账或改写数字

**候选数字口径的坑** (v1.6.4 实测):

- LaTeX 里裸 `%` 是注释符 → `71.8%` 会把**该行后半段全吞掉**.
  论文里必须写 `71.8\%`; check 65 沿用 LaTeX 语义 (与编译器一致), 不会误判.
- 旧版 `number_ledger.py` 用硬编码文件清单 (且文件名带空格, 与模板实际文件名不符) →
  扫不到文件 → 匹配率虚高 100% → **check 形同虚设**. v1.6.4 已改为自动枚举 + 公共函数复用.

## 6. dryrun check 55 (L22) 协同

`references/scripts/dryrun.py` `check_number_source` (v1.5.8.2 新增):

- 扫论文 11 章节 .tex, 找**关键判据** (Bi / Fo / 收缩率 / Re / Pr / 等) 出现位置
- 检测来源标记: 紧邻文字应含 "实算" / "print" / "resultX.xlsx" / "代码" / "solver 算" 等
- 判断:
  - 含可信来源 → **green**
  - 关键判据出现但无来源 → **yellow 警告** (提示补公式 + 二次复算)
  - 找不到关键判据 → **yellow 跳过** (非机理题无 Bi/Fo)
