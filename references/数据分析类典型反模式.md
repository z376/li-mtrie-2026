# 数据分析类典型反模式 (v1.5.7.14 新增, 数据分析题类适配)

> **⚠️ 适用题类**: CUMCM **C 题 (本科数据分析类, 历年) + 大数据/机器学习/统计建模类**. 核心特征: **数据预处理 + 特征工程 + 模型训练 + 评价指标** (分类/回归/聚类/时序预测), 通常**不涉及物理机理**, 以**统计学习**为核心.

> **5 道防线使用**: 防线 1 (流程修剪) + 防线 3 (设计意图) + 防线 4 (指针强化) **完全适用**; 防线 2 (数据隔离, 0:00 决策) **不适用** (但**数据使用纪律**仍要遵守 — 不能用未来信息); 防线 5 (三口径) **部分适用** (用"训练-测试划分 + 评价指标" 替代).

---

## 1. 数据分析类典型反模式

| # | 反模式 | 防线 | 修正做法 |
|---|--------|------|---------|
| 1 | 数据预处理不报告 (e.g. 缺失值填充/异常值处理没说) | 1 | **论文 §3 详细报告**: 缺失率/异常率/填充方法/标准化方法 |
| 2 | 训练-测试划分不报告 (e.g. 随机划分 vs 时序划分混淆) | 1 | **明确划分方法**: 时序预测用前 80% 训练 后 20% 测试; 分类用 stratified split + 报告 seed |
| 3 | 评价指标选错 (e.g. 类别不平衡用 accuracy) | 1/5 | 类别不平衡用 **F1/AUC**; 回归用 RMSE/MAE + R²; 多分类用 macro-F1 |
| 4 | 特征工程"堆砌" (e.g. 加 100 个特征没筛选) | 3 | **特征选择**: importance / SHAP / L1 正则, 论文报告 top-10 |
| 5 | 模型选择没对比 (e.g. 直接用 XGBoost 没跟 LR/RF 比) | 3 | **至少 3 模型对比** (基线 + 主流 + 高级), 报告表格 + 选择理由 |
| 6 | 训练-测试 gap 大 (e.g. 训练 99%, 测试 70%) | 3 | **过拟合处理**: 正则化 / dropout / 早停 / 简化模型 + gap < 10% |
| 7 | 类别不平衡没处理 (e.g. 9:1 不平衡直接训) | 3 | **SMOTE / class_weight / focal loss**, 论文报告处理前后 F1 差距 |
| 8 | 报告指标没附置信区间 (e.g. 只报"准确率 90%") | 1 | **多次随机种子** (e.g. seed=0/1/2/3/4) 取 mean ± std |
| 9 | 模型可解释性缺失 (e.g. 深度学习黑盒直接给结论) | 1 | **可解释性**: SHAP / LIME / 特征 importance, 论文报告 |
| 10 | 测试集"漏"到训练 (e.g. 数据泄露 — 用未来信息预测) | 2 (变体) | **时序严格**: 训练集只在历史; 测试集只在未来 (评阅对应章节 "数据使用" 条款) |

**典型例题**: 用户画像分类 / 疾病预测 / 销售预测 / 信用评分 / 异常检测 / 推荐系统.

## 2. 跑题前自检 checklist (数据分析类)

- [ ] **数据预处理报告**: §3.1 缺失值率/异常值率/填充方法/标准化方法 完整列出
- [ ] **训练-测试划分**: §3.2 写明划分方法 + 比例 + 划分原则 (随机/时序/stratified)
- [ ] **评价指标选择**: §3.3 写明为什么用这指标 (e.g. 类别不平衡用 F1, 不用 accuracy)
- [ ] **基线模型**: §4 报告 LR/RF 等基线, 至少 3 模型对比
- [ ] **特征工程**: §3.4 报告特征选择方法 (importance/SHAP/L1) + top-10 特征
- [ ] **类别不平衡处理** (如适用): §3.5 报告 SMOTE/class_weight 等
- [ ] **可解释性计划**: §4 末尾写 SHAP/LIME 等可解释性方法
- [ ] **时序严格性** (如适用): 训练集仅历史, 测试集仅未来, 不能混
- [ ] **期望结果方向**: §4 写"训练-测试 gap < 10%" 或"F1 > 0.85" 等量化指标

## 3. 跑完后期望对照 checklist (数据分析类)

| 检查项 | 期望方向 | 量化判据 | 实际值 | 命中? |
|--------|---------|---------|--------|-------|
| 训练-测试 gap | gap < 10% | 训练指标 - 测试指标 < 10% | ___ | ☐ |
| 关键指标 | F1 / RMSE / AUC 等 | 跟基线模型对比显著提升 | ___ | ☐ |
| 类别不平衡 | F1 显著 > accuracy | F1 vs accuracy 报对照 | ___ | ☐ |
| 异常值检测 | 检测率 > 90% | 检出已知异常 | ___ | ☐ |
| 特征 importance | top-5 特征有物理/业务意义 | importance 排序合理 | ___ | ☐ |
| 多次随机种子稳定性 | mean ± std | std < 5% | ___ | ☐ |

**不命中**: ✗ → 检查 (1) 数据预处理是否漏报 (2) 训练-测试划分是否时序严格 (3) 评价指标是否合适 (4) 模型是否过拟合 (5) 类别不平衡是否处理.

## 4. 数据使用纪律 (变体 — 不是 0:00 决策但仍是数据使用)

CUMCM 数据分析题, **时序严格性**是关键:

| 数据 | 训练集能用? | 测试集能用? |
|------|------------|------------|
| 历史 (t < train_end) | ✓ | ✓ (参考基准) |
| **未来** (t > train_end) | ✗ **数据泄露** | ✓ (待预测) |
| 测试集 ground truth | ✗ | ✗ (评阅保留) |

评阅要点对应章节 "数据使用" 条款 (每年 4 月公布, 跑题前查最新): 不能用测试集 ground truth 训练, 不能用未来信息做特征.

**典型坑**: 用户画像分类时, 把"未来某天的标签"加入当前样本的特征 → 数据泄露, 评阅 0 分.
