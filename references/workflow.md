# 数学建模竞赛 Skill — 完整工作流

> 读题 → 计划（多模型对比 → 用户选择）→ 求解 → 论文 → 编译

**2026 规范对齐**：本工作流按 2026 年全国大学生数学建模竞赛论文格式规范
（2026 年修订稿，2026-09-01 起试行）+《人工智能工具使用规定（2026 年试行）》
更新，重点：
- 题组判断（本科 ABC / 高职 DE）
- 摘要一律中文，不要目录，正文 ≤ 30 页
- 附录两段固定说明（程序/支撑材料）
- 论文版与电子版**两套入口**（`论文.tex` 用 `withpreface`，`电子版.tex` 用 `electronic`）
- AI 工具使用声明放**参考文献之前**（不是附录）
- AI 工具使用详情 PDF 放**支撑材料**（不是附录）

## 执行流程

### Step 0：读取输入

- 读取 `题目/` 下 PDF/DOCX
- 读取 `数据/` 下所有 xlsx/docx/csv，**全量读取**，检查：列数一致性、数据类型、合并单元格、多级表头、隐藏 sheet
- 打印数据总览，识别问题数量 N

### Step 1：求解计划（含模型比选）

读完题后，**先不写完整计划**，而是为每个问题列出候选模型的对比分析，供用户选择。

#### 1.0 整题建模主线（先画全篇骨架，再分问）

**关键判断**：每年评委会的加分项里，"全篇思路连贯"比"每问用了什么花哨算法"更重要。
所以在给每问列候选模型前，**先**回答 3 个全篇级问题：

**Q1：全篇的研究对象和中心矛盾是什么？**（一句话）

模板：本题研究 ______（研究对象），其核心矛盾是 ______（如：效率 vs 公平、机理 vs 数据、局部最优 vs 全局最优），最终目标是在 ______ 约束下实现 ______。

**Q2：跨问题联动链是什么？**（哪问的输出是另一问的输入？）

常见模式（**评委会一看就懂**的 6 种）：

| 联动模式 | 典型用法 | 关键注意点 |
|----------|---------|------------|
| 机理→计算→精度 | 后问给前问加修正项 | 保持状态量/坐标系一致 |
| 描述→估计→预测→决策 | 估计/预测结果喂给决策 | 传递领域知识和不确定性 |
| 单例→多主体/阶段 | 同一仿真器多场景复用 | 加协调/分配/递归/复杂度 |
| 确定性→不确定→稳健 | 参数状态变化 | 保约束，加场景/分布/风险 |
| 单因素→多因素 | 后问个性化/扩展 | 保可运行输出，对比改进 |
| 分类→优化 | 预测控制决策 | 防数据泄露，审计决策误差 |

写明：哪问 → 输出什么 → 哪问输入 → 当作什么用（参数/初值/约束/验证集）。

**Q3：全文统一的符号表是什么？**（不是问题内部的，是跨问的）

> 这部分**直接写到论文第 4 章「符号说明」**，避免符号混用。详见 `paper-spec.md` 第 4 章。
> 关键字段：研究对象集合 / 索引 / 决策变量 / 共享参数 / 单位 / 坐标系 / 时间约定 / 评价指标。

**Q4（可选）：Mermaid 联动流程图**

```mermaid
flowchart LR
    A[问题1: 数据预处理] --> B[问题2: 影响因素分析]
    B --> C[问题3: 预测模型]
    C --> D[问题4: 优化调度]
    B -.验证.-> D
```

把跨问题数据/参数/约束的传递画清楚——评委会看图秒懂你全篇思路。

#### 1a. 模型比选

#### 1a. 模型比选

对每个问题，列出 3-4 个候选模型/方法，逐一说明：

```
问题X：<问题简述>

| 方案 | 核心方法 | 优点 | 缺点 | 适用条件 |
|------|---------|------|------|---------|
| 方案A | （具体算法名） | （2-3条） | （1-2条） | （数据/假设要求） |
| 方案B | ... | ... | ... | ... |
| 方案C | ... | ... | ... | ... |

推荐：方案X，理由：...
```

模型选择要点：

- 问题本质定性（优化/评价/预测/分类/机理）→ 匹配对应类型的方法
- **有数据的题目**：至少包含一个机器学习/统计模型 + 一个传统机理模型
- **优化类题目**：至少包含一个精确算法 + 一个启发式算法
- **评价类题目**：至少包含主观赋权法（AHP）+ 客观赋权法（熵权/CRITIC）

候选模型池：

| 问题类型 | 候选模型池 |
|----------|-----------|
| 优化类 | 线性/整数规划、遗传算法(GA)、粒子群(PSO)、模拟退火(SA)、蚁群(ACO) |
| 评价类 | 熵权法、AHP层次分析、TOPSIS、模糊综合评价、CRITIC、灰色关联 |
| 预测类 | 时间序列(ARIMA)、随机森林、XGBoost、LSTM、灰色预测GM(1,1)、多元回归 |
| 分类/识别 | 逻辑回归、SVM、随机森林、KNN、朴素贝叶斯、CNN |
| 机理分析 | 微分方程、动力学建模、元胞自动机、Agent-Based模型 |

#### 1b. 用户选择

将对比表展示给用户，**等待用户选择每个问题的方案**。用户选择后，再写完整的 `求解/求解计划.md`，按选定方案细化求解思路和具体参数。

#### 1c. ⚠️ 8 项整篇一致性自检 — **每个问题求解后必须回填**（硬性要求）

> **8 项自检模板见 `references/paper-spec.md §4.0`**（符号一致性 / 共享参数 / 后问继承 / 硬约束可验证 / 不确定性传递 / 独立验证 / 输出表齐全 / 候选方案同指标）。本节不重复列，只讲"如何回填"。

> **踩坑教训**：2024 国赛测试时，这 8 项只作为"占位"，跑完 5 个问题后**没回填**，
> 结果发现：问题 2 复用了问题 1 的"碰撞距离阈值"但没显式声明；问题 4 的"调头半径 r1=4.5"
> 是拍脑袋的值，没和"问题 3 的最小螺距"联动。
>
> **强制要求**：**每写完一个问题的代码，必须在 `求解/求解计划.md` 末尾的"自检"区逐项回填**。
> 不回填不算完成该问题。

**回填格式**（每个问题结束后复制一份到 `求解/求解计划.md` 末尾，按 paper-spec.md §4.0 的 8 项逐条 [x]）：

```markdown
## 8 项整篇一致性自检（每个问题完成后回填）

### 问题 1 ✅
- [x] 符号、坐标、时间、单位系统与全篇一致？（具体说明）
- [x] 共享参数 p=0.55, L=2.20m, d=0.275m 一次估出且复用？（具体值）
- [x] 本问无继承自前问的输出（第一问）/ 本问继承自问题 N 的 X（具体值）
- [x] 硬约束 ... 可验证（程序 round(6) / min_sep ≥ ...）
- [x] 不确定性 N/A / 95% CI 传至问题 N
- [x] t=0..300 龙头位置独立验证：t=0 在 (8.8, 0) 第 16 圈 ✓
- [x] result1.xlsx N 个 sheet 完整生成（位置+速度, 448×302 + 224×302）
- [x] 各候选方案对比已记录在 `求解计划.md`

### 问题 2 ✅
...
```

**踩坑检查**（每问必跑这 5 个问题）：
1. **跨问题参数复用了吗？**（如问题 1 估的 p, L 在问题 3 还在用吗？是否一致？）
2. **后问的输入是不是前问的输出？**（如问题 2 的"碰撞距离阈值"是 0.30m 吗？问题 1 估的？）
3. **硬约束能程序化验证吗？**（如"不碰撞" → 检查 `min_sep ≥ 板宽`）
4. **每个最优/预测结果有独立验证吗？**（如龙头 t=0 位置能用手算 `r=pθ/(2π)` 验证）
5. **每个输出表/文件按题目列表生成吗？**（result1/2/4 全到位）

**必看输出**：

1. **列类型识别对不对？**
   - 数字 ID 被识别成 `continuous` 或 `ordinal` 是常见误判——手动标成 `categorical` 或 `text`
   - 类别数 ≤ 7 的整数（如 Likert 1-5）会被识别成 `ordinal`，是否符合题意？
2. **每组 n 是多少？**
   - n < 10 警告 —— 不能用均值柱，要叠加原始点（详见 `references/绘图规范.md`）
   - n < 3 强警告 —— 直接画散点，不画统计图
3. **是否高度偏态？**（|skew| > 1）
   - 对数轴 / 变换后再画
4. **缺失率** —— > 20% 的列考虑删除或单独说明
5. **相关性** —— 强相关（|r| > 0.8）的两个变量同时入模会多重共线性

**程序输出的「初步图型建议」**只能作参考——最终图型选择必须结合**论证目标**
（你想说什么），详见 `references/绘图规范.md` 顶部的"决策三轴"。

## 论文核心规则

### 禁止事项（违反即扣分）

| 禁止 | 例外 |
|------|------|
| 正文分点符号（①②③、●○、1.2.3.） | 模型假设/评价的 itemize |
| 正文加粗 `\textbf{}` | 摘要"对于问题X"、问题重述"问题N："、假设/优缺点头部 |
| 全文 `\newpage` | 仅参考文献和附录前可用 |
| 图上 `set_title()` | 标题由 `\caption{}` 承担 |
| 表格换行 | 格子文字一行显示 |
| 摘要超 1 页或含公式 | — |

### 各章关键约束

**0. 摘要**：开头 ≤30 字 + 逐问（按类型选模板）+ 结尾 ≤20 字 = 总计 ≤900 字。编译后验证 `abstract:end` label 在第 1 页。

**1. 引言**：背景 2-3 段（宏观→困境→渴求），问题重述每条 `\textbf{问题N：}` ≤2 行。

**2. 总体分析**：三段纯文字，**不画流程图**。

**3. 模型假设**：itemize，`\textbf{假设N：}`，数量 ≈ 问题数。

**4. 符号说明**：`longtable`，列宽比例总和 = 1.04 − 0.04×N。

**5. 模型的建立与求解**（核心，占全文 50-60%）：

- 每问的分析流程图：9 框 TikZ 模板，只改 `{}` 中文字，每框 ≤7 字，箭头布局不动
- 建模步骤按问题类型走：优化类（目标→约束→机理→算法）、评价类（指标→权重→综合评价）、预测类（特征→模型→训练评估）
- 每问 ≥6 个公式，核心步骤公式密集，公式间用"将式(X)代入式(Y)""进一步展开得"串联
- 每个公式后跟"其中，$X$表示…"变量说明段
- **优化类必须完整写出目标函数+决策变量+约束条件**，不可用文字概括

**6. 模型检验**：误差分析（5折交叉验证，$R^2$/RMSE/MAE/MAPE）+ 灵敏度分析（参数 ±20%）

**7. 模型评价**：优点 4 + 缺点 2，**按模型写不按问题写**

**8. 模型改进与推广**：各一段自然段落

**9. 参考文献**：8-15 条，GB/T 7714-2015，优先中文。标签：中文=作者拼音+年份，英文=姓+年份+关键词。**禁止** `\emph{}` `\textbf{}`，删除 DOI。每条必须在正文有 `\cite{}`。

**10. 附录**：`longtable` 两列附件说明表。

### 图表规范

- 图宽 `0.8\textwidth`，表宽 `\textwidth`
- 所有表格统一 `longtable` + `>{\centering\arraybackslash}p{}`
- caption/label 格式：`\caption{...}\label{tab:xxx}\\`，caption 在 label 前
- 图文件通过相对路径引用：`../求解/问题X/图片/xxx.png`

### 图路径规范（B4 踩坑教训，必看）

> xelatex 编译时工作目录是 `论文/`，不是项目根目录。**所有 `\includegraphics` 路径从 `论文/` 起算**。

**路径映射表**：

| 你的意图 | 错的写法 | 正确写法 |
|---------|---------|---------|
| 引用问题 1 的图 | `求解/问题1/图片/龙头轨迹.png` | `../求解/问题1/图片/龙头轨迹.png` |
| 引用问题 3 的图 | `../../求解/问题3/图片/pitch.png` | `../求解/问题3/图片/pitch.png` |
| 引用电子版 PDF 的图（极少） | `图片/xxx.png`（在 `论文/` 下建子目录）| `图片/xxx.png`（仅当图就在 `论文/` 下）|
| 绝对路径（**禁止**）| `D:\Math\求解\问题1\图片\xxx.png` | 不允许，换电脑就坏 |

**编译报错对照表**：

| 报错 | 原因 | 修复 |
|------|------|------|
| `! LaTeX Error: File 'xxx.png' not found.` | 路径错了（多半少一个 `..`） | 从 `论文/` 起算，前面加 `..` |
| `! Unable to load picture or PDF file.` | PNG 文件本身坏了 / 路径含中文编码异常 | 用英文文件名重命名；或换台电脑试 |
| 图能编但显示空框 | 用了 `draft` 模式 | 编译命令去掉 `-draftmode` 或 `\documentclass[draft]{...}` |

**自检脚本**（编译前手动跑一次，列图存在性）：

```powershell
# 在论文/ 目录下跑
$figs = Get-ChildItem -Path ..\求解 -Recurse -Include *.png
foreach ($f in $figs) {
  $rel = $f.FullName.Replace((Get-Location).Path + '\..\', '')
  $rel = $rel -replace '\\', '/'
  Write-Host "../$rel  ← 检查 .tex 里 \includegraphics 路径是否一致"
}
```

**统一规范**：
- 所有 PNG 文件名用**英文 + 下划线**（不要中文 + 空格）
- 路径里**禁止**空格、括号（`(` `)` 会让某些 xelatex 引擎报错）
- 推荐相对路径**始终从 `../求解/...` 起步**，不要用绝对路径

## 常见错误（求解和写论文时主动避开）

1. ❌ 公式堆砌无串联 → ✅ 每个公式前后有中文过渡句
2. ❌ 变量无说明 → ✅ 每个公式后跟"其中，$X$表示…"
3. ❌ 表格用 `tabular`/`tabularx` → ✅ 统一 `longtable` + `p{}`
4. ❌ 图上写标题 → ✅ 标题放在 `\caption{}`
5. ❌ 图表无引用 → ✅ "如图X所示""如表X所示"
6. ❌ 分点符号 → ✅ 自然段落
7. ❌ 摘要超页 → ✅ 编译后验证，超了就缩减
8. ❌ 参考文献无引用 → ✅ 每条 `\bibitem` 对应正文 `\cite`
9. ❌ 优化模型只写文字 → ✅ 完整写出目标函数+约束+变量
10. ❌ 模型检验缺失 → ✅ 交叉验证+灵敏度分析缺一不可
