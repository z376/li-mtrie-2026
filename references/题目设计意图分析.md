# 题目设计意图分析 (v1.5.7.7 新增, 防"按字面跑不解题")

> **核心原则**: CUMCM 题目是**研究性问题**, 不是"按字面跑 LP". 题目设计有**递进关系**和**隐含期望方向**, 跑完后**必须验证期望**, 不达预期就要回头改方法.

> **来源**: 2026 C 题实战暴露. 我 (Mavis) 之前测 skill 只看"流程跑通", 没看"解题方法是否对" — Q3 紧急购电**应该比 Q2 低** (滚动调整应压缩紧急购电), 但我跑出来 Q3 (362/365, e=329.7万 kWh) 比 Q2 (315/334, e=259.0万 kWh) **还多**, 说明**方法错或预报精度不足**, 必须回头改. 这是**测试 skill 的根本盲点**.

---

## 1. 三类必识别信息

跑题前必须识别 3 件事:

| 类别 | 问什么 | 答错后果 |
|------|--------|---------|
| **递进关系** | N 个问题间的逻辑链条 (前 → 后 是**机制 → 优化 → 加维度**?) | 不知道 Q3 是 Q2 的优化, 写不出对比分析 |
| **每个问题测什么** | 1-2 句话 (e.g. "无预报场景, 紧急购电 5x 代价") | 不知道本题的**研究价值**, 跑出来啥算对 |
| **期望结果方向** | 列每个问题的**关键指标**期望 (e.g. Q3 e < Q2) | 跑完没对账, 方法错也不知道 |

---

## 2. 4 步法 (跑题前 + 跑完验证)

```
Step 1: 画递进图
  ↓
Step 2: 每个问题测什么 (1-2 句话)
  ↓
Step 3: 期望方向 (列关键指标 + 期望值)
  ↓
Step 4: 跑完后对照期望, 不达预期 → 回头改方法
```

### Step 1: 画递进图

把 N 个问题按**逻辑链条**画出来, 标注**前后关系**:

```
Q1 (基线)  →  Q2 (提出机制)  →  Q3 (优化机制)  →  Q4 (加维度)
```

**判定**: 看题目是不是按 "基线 → 机制 → 优化 → 加维度" 排列. 如果是, 每个问题的**角色**就清楚了.

### Step 2: 每个问题测什么 (1-2 句话)

e.g. (2026 C 题):
- **Q1**: 单日 LP 基线 (验证模型正确性)
- **Q2**: 无预报场景, 紧急购电 5x 触发代价 (历史预测的误差累积)
- **Q3**: 滚动调整压缩紧急购电的能力 (4 时点 MPC + 双向偏差)
- **Q4**: 波动电价下储能套利 + 避免高价时段紧急购电

### Step 3: 期望方向

e.g.:
- Q1: 总费最优 (跟官方评阅要点参考值匹配 ✓)
- **Q2**: 紧急购电 > 0 (物理真实, 不是 0)
- **Q3**: 紧急购电 < Q2 (滚动调整应**压缩**); 调整偏差 < Q2 紧急购电费 (净收益)
- **Q4-3**: 紧急购电**转移到低价时段** (时段分布变化, 不是绝对量降低)

### Step 4: 跑完对照

跑完后**逐项验证**:
- ✓ 期望命中 → 方法对
- ✗ 期望未命中 → **方法错**, 回头改 (e.g. 换预测数据源, 减少滚动次数, 改套利策略)

**不能**找借口"数据不真实" 跳过 — 题目就是用给定的数据, 方法不对就是不对.

## 3. 反模式 (踩过的坑)

### ❌ 反模式 1: 只看"流程跑通", 不看"解题是否对"
```python
# 跑完 Q3, 输出 "Q3 完成, 紧急购电 329.7 万 kWh"
# 没对照期望 "Q3 e < Q2 e" → Q3 紧急购电比 Q2 多 = **方法错**, 没回头改
```

**修**: 跑完**逐项验证期望**, 不达预期**必须回头改方法**, 不能跳过.

### ❌ 反模式 2: 期望值拍脑袋, 没量化
```python
# "Q3 应该比 Q2 紧急购电少" — 少多少? 没量化 → 跑出来"少 5%" 也算"对", 但 5% 可能不显著
```

**修**: 期望值要**量化**, e.g. "Q3 紧急购电**至少**比 Q2 少 30% (调整偏差 + 滚动预报的净收益)". 跑完**算 %**, 不达 30% 回头改.

### ❌ 反模式 3: 不达期望, 找借口 (而不是改方法)
```python
# Q3 e > Q2 e, 说 "附件 3 预报误差太大, 不是方法错"
# 实际: 即使误差大, 调整偏差 ≤ 紧急购电费才是净收益, Q3 总费应 < Q2
```

**修**: 不达期望 = **方法错** (or 数据假设错), **改方法**或**改假设**, 不能用"数据不真实"当借口.

## 4. 实战案例 (2026 C 题)

### 4.1 递进关系识别 (按题目顺序)

| 问题 | 测什么 | 期望方向 (跑前) | 实际 (跑后) | 验证结果 |
|------|-------|----------------|------------|---------|
| Q1 | 单日 LP 基线 | 总费 35,127 元 ± 5% | 35,127 元 ✓ | ✓ 跟官方参考 59482.70 kWh / 35126.95 元 一致 |
| Q2 | 紧急购电 5x 代价 | 紧急购电 > 0 (物理真实) | 紧急购电 315/334 (94.3%) ✓ | ✓ |
| **Q3** | **滚动调整压缩紧急购电** | **Q3 e < Q2 e (期望下降 30%+)** | **Q3 e=329.7万 > Q2 e=259.0万** | ✗ **方向错, 方法需改** |
| **Q4** | **波动电价下避免高价紧急购电** | **Q4-3 e 转移到低价时段** | **Q4-3 e=333.8万 ≈ Q3 e=329.7万** | ✗ **没体现避免高价** |

### 4.2 不达期望的根因分析

**Q3 紧急购电 > Q2 的根因**:
- 附件 3 预报误差 (1-5%) **累积触发**更多紧急购电
- 滚动调整次数太多 (4 时点 = 5 次 LP), **每次调整都引入新误差**
- **正解应该是**: 用**前一天实际** (Q2 已验证, 误差小) 替代附件 3 0:00 预报; 或**减少滚动次数** (只在 12:00 一次调整)

**Q4-3 紧急购电 ≈ Q3 的根因**:
- 储能 SOC 起始 6000 (50%), 没考虑**高电价时段前预充**
- **正解应该是**: 在低电价时段**主动充电到 SOC_max (10800)**, 高电价时段前**预防性预充**, 让 SOC 满避免紧急购电
- 这才是**储能套利** 的真正价值, 不是"被动作 LP"

### 4.3 修正方案 (跑题用户应做的)

如果跑出来不达期望, **不能**接受"现实如此", 应该:
1. **回头看题目设计意图** (这问题为什么在测这个?)
2. **改方法**: e.g. 换预测数据源 (前一天实际), 减少滚动次数, 改初始 SOC, 加套利优化层
3. **重跑**: 验证修正后是否达期望
5. **写论文**: 诚实写"原方法 X 不达期望 Y, 改方法 X' 达期望", 这是**论文加分项**

## 6. 给跑题用户的 1 个核心问题

跑完每个问题, **自问 1 句**:

> "**这个问题的结果符合题目设计意图吗?** 如果不符合, **改方法** 或**改假设**, 不能接受'现实如此'."

这是 skill 测试的核心 — **跑通 ≠ 解对**, **解对 = 期望命中 + 方法合理 + 数据隔离**.
