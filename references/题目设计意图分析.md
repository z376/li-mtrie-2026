# 题目设计意图分析 (v1.5.7.7 新增, 防"按字面跑不解题")

> **核心原则**: CUMCM 题目是**研究性问题**, 不是"按字面跑 LP". 题目设计有**递进关系**和**隐含期望方向**, 跑完后**必须验证期望**, 不达预期就要回头改方法.

> **来源**: 调度类实战暴露. 我 (Mavis) 之前测 skill 只看"流程跑通", 没看"解题方法是否对" — Q3 紧急购电**应该比 Q2 低** (滚动调整应压缩紧急购电), 但我跑出来 Q3 (362/365, e=329.7 万) 比 Q2 (315/334, e=259.0 万) **还多**, 说明**方法错或预报精度不足**, 必须回头改. 这是**测试 skill 的根本盲点**.

---

## 1. 三类必识别信息

跑题前必须识别 3 件事:

| 类别 | 问什么 | 答错后果 |
|------|--------|---------|
| **递进关系** | N 个问题间的逻辑链条 (前 → 后 是**机制 → 优化 → 加维度**?) | 不知道 Q3 是 Q2 的优化, 写不出对比分析 |
| **每个问题测什么** | 1-2 句话 (e.g. "无预报场景, 紧急购电 5x 代价") | 不知道本题的**研究价值**, 跑出来啥算对 |
| **期望结果方向** | 列每个问题的**关键指标**期望 (e.g. Q3 e < Q2) | 跑完没对账, 方法错也不知道 |

---

## 2. 4 步法 (跑题前 + 跑完验证)

```
Step 1: 画递进图
  ↓
Step 2: 每个问题测什么 (1-2 句话)
  ↓
Step 3: 期望方向 (列关键指标 + 期望值)
  ↓
Step 4: 跑完后对照期望, 不达预期 → 回头改方法
```

### Step 1: 画递进图

把 N 个问题按**逻辑链条**画出来, 标注**前后关系**:

```
Q1 (基线)  →  Q2 (提出机制)  →  Q3 (优化机制)  →  Q4 (加维度)
```

**判定**: 看题目是不是按 "基线 → 机制 → 优化 → 加维度" 排列. 如果是, 每个问题的**角色**就清楚了.

### Step 2: 每个问题测什么 (1-2 句话)

e.g. (调度类):
- **Q1**: 单日 LP 基线 (验证模型正确性)
- **Q2**: 无预报场景, 紧急购电 5x 触发代价 (历史预测的误差累积)
- **Q3**: 滚动调整压缩紧急购电的能力 (4 时点 MPC + 双向偏差)
- **Q4**: 波动电价下储能套利 + 避免高价时段紧急购电

### Step 3: 期望方向

e.g.:
- Q1: 总费最优 (跟官方评阅要点参考值匹配 ✓)
- **Q2**: 紧急购电 > 0 (物理真实, 不是 0)
- **Q3**: 紧急购电 < Q2 (滚动调整应**压缩**); 调整偏差 < Q2 紧急购电费 (净收益)
- **Q4-3**: 紧急购电**转移到低价时段** (时段分布变化, 不是绝对量降低)

### Step 4: 跑完对照

跑完后**逐项验证**:
- ✓ 期望命中 → 方法对
- ✗ 期望未命中 → **方法错**, 回头改 (e.g. 换预测数据源, 减少滚动次数, 改套利策略)

**不能**找借口"数据不真实" 跳过 — 题目就是用给定的数据, 方法不对就是不对.

## 3. 反模式 (踩过的坑)

### ❌ 反模式 1: 只看"流程跑通", 不看"解题是否对"
```python
# 跑完 Q3, 输出 "Q3 完成, 紧急购电 329.7 万 kWh"
# 没对照期望 "Q3 e < Q2 e" → Q3 紧急购电比 Q2 多 = **方法错**, 没回头改
```

**修**: 跑完**逐项验证期望**, 不达预期**必须回头改方法**, 不能跳过.

### ❌ 反模式 2: 期望值拍脑袋, 没量化
```python
# "Q3 应该比 Q2 紧急购电少" — 少多少? 没量化 → 跑出来"少 5%" 也算"对", 但 5% 可能不显著
```

**修**: 期望值要**量化**, e.g. "Q3 紧急购电**至少**比 Q2 少 30% (调整偏差 + 滚动预报的净收益)". 跑完**算 %**, 不达 30% 回头改.

### ❌ 反模式 3: 不达期望, 找借口 (而不是改方法)
```python
# Q3 e > Q2 e, 说 "附件 3 预报误差太大, 不是方法错"
# 实际: 即使误差大, 调整偏差 ≤ 紧急购电费才是净收益, Q3 总费应 < Q2
```

**修**: 不达期望 = **方法错** (or 数据假设错), **改方法**或**改假设**, 不能用"数据不真实"当借口.

## 4. 实战案例 (调度类)

### 4.1 递进关系识别 (按题目顺序)

| 问题 | 测什么 | 期望方向 (跑前) | 实际 (跑后) | 验证结果 |
|------|-------|----------------|------------|---------|
| Q1 | 单日 LP 基线 | 总费 35,127 元 ± 5% | 35,127 元 ✓ | ✓ 跟官方参考 X kWh (基础参考值) / Y 元 (基础参考值) 一致 |
| Q2 | 紧急购电 5x 代价 | 紧急购电 > 0 (物理真实) | 紧急购电 315/334 (94.3%) ✓ | ✓ |
| **Q3** | **滚动调整压缩紧急购电** | **Q3 e < Q2 e (期望下降 30%+)** | **Q3 e=329.7万 > Q2 e=259.0万** | ✗ **方向错, 方法需改** |
| **Q4** | **波动电价下避免高价紧急购电** | **Q4-3 e 转移到低价时段** | **Q4-3 e=333.8万 ≈ Q3 e=329.7万** | ✗ **没体现避免高价** |

### 4.2 不达期望的根因分析

**Q3 紧急购电 > Q2 的根因**:
- 附件 3 预报误差 (1-5%) **累积触发**更多紧急购电
- 滚动调整次数太多 (4 时点 = 5 次 LP), **每次调整都引入新误差**
- **正解应该是**: 用**前一天实际** (Q2 已验证, 误差小) 替代附件 3 0:00 预报; 或**减少滚动次数** (只在 12:00 一次调整)

**Q4-3 紧急购电 ≈ Q3 的根因**:
- 储能 SOC 起始 6000 (50%), 没考虑**高电价时段前预充**
- **正解应该是**: 在低电价时段**主动充电到 SOC_max (10800)**, 高电价时段前**预防性预充**, 让 SOC 满避免紧急购电
- 这才是**储能套利** 的真正价值, 不是"被动作 LP"

### 4.3 修正方案 (跑题用户应做的)

如果跑出来不达期望, **不能**接受"现实如此", 应该:
1. **回头看题目设计意图** (这问题为什么在测这个?)
2. **改方法**: e.g. 换预测数据源 (前一天实际), 减少滚动次数, 改初始 SOC, 加套利优化层
3. **重跑**: 验证修正后是否达期望
5. **写论文**: 诚实写"原方法 X 不达期望 Y, 改方法 X' 达期望", 这是**论文加分项**

## 6. 三口径铁律 (v1.5.7.9 新增, 总费 ≠ 紧急购电费 ≠ 调整偏差)

> **⚠️ 适用题类 (v1.5.7.13 补充)**: **调度/滚动决策类题** 专属. 核心特征: 0:00 制定计划 + 执行 + 偏差调整, 三段成本结构清晰. **物理机理题/数据分析题 不适用** (这类题没有"计划 vs 紧急 vs 调整"的多口径成本结构). 物理题/数据题按本题期望方向 (e.g. 物理题 = 单口径误差最小; 数据题 = 单口径评价指标) 处理.

CUMCM 调度/调度类题, **总费用**有 3 个独立组成部分, 不能混算也不能对比错位:

| 口径 | 计算 | 用什么电价/价格 | 含义 |
|------|------|----------------|------|
| **计划购电费** | Σ c_t × g_plan[t] | 用**预测电价** (0:00 已知的前一天电价, 或附件 M 预报) | 0:00 LP 优化的目标 |
| **紧急购电费** | Σ 5 × c_t × e[t] | 用**当天实际电价** × 5 (§4.1 电价与缺口相关性) | 实际执行时缺口的代价 |
| **调整偏差费** | Σ (0.5/1.5) × c_t × |g_adj - g_plan| | 用**当时实际电价** | 滚动调整与原计划的偏差代价 |

**总费用 = 计划 + 紧急 + 调整** (3 部分独立加总)

**关键陷阱** (我之前踩的):

1. **❌ Q3 总费不一定比 Q2 低**: 因为 Q3 加了调整偏差费, 但**紧急购电费应**比 Q2 **低**. 总费对比**不能**只看数字, 必须**分项对比**.
2. **❌ 紧急购电费不能用预测电价**: §4.1 "电价与供电缺口具有相关性" → 缺电时电价高 → 紧急购电**必须用当天实际电价** × 5, 不能用预测电价算 (那是把"未来信息"提前算).
3. **❌ 调整偏差系数按双向**: 少买 0.5x (g_plan > g_adj), 多买 1.5x (g_adj > g_plan). 这意味着**调整幅度小** = 调整偏差低, **鼓励接近原计划**.

**写论文 §5.X 必须分项列**总费用 = 计划 + 紧急 + 调整, 跑题用户**必做**. 模板:

```
总费用: 2207.7 万元
  计划购电费: 1146.7 万元  ← 用预测电价
  紧急购电费: 1061.0 万元  ← 用当天实际电价 × 5
  (调整偏差费: 0 万元     ← 仅 Q3/Q4 有)
```

dryrun check 23: 扫 .py 总费计算, 如果 `cost_total = ...` 混了 3 个口径 (e.g. 漏加调整偏差), 报 yellow 警告.

## 7. 数据物理真实性标注 (v1.5.7.9 新增, 防"修正数据造假")

> **⚠️ 适用题类 (v1.5.7.13 补充)**: **通用** — 所有 CUMCM 题类都适用. CUMCM 数据由出题组合成, 任何题类都可能遇到"数据物理不真实" (调度题 PV 偏强 / 物理题初始条件理想化 / 数据题类别分布极端). 核心要点都是**不修正数据, 标注 + 直接使用**.

CUMCM 数据由**出题组合成**, 经常有**物理不真实** (e.g. 附件 2 全年 PV max > 8000 kW, 无一天阴雨). 跑题用户**容易误以为**数据错, 试图"修正数据" (人造阴雨天/缩 g 上界/加噪声), 但这是**造假**, 评阅会扣分.

**正确做法**: **标注数据物理不真实**, 在论文 §5.2.2 (数据预处理章节) 诚实写:

```
> **附件 2 数据观察**: 全年 365 天 PV max > 8000 kW, 相邻天 = 0.995 (无阴雨).
> 物理上不符合 MH/IL 实际气象分布 (应有不少阴雨天, PV max < 3000 kW).
> 但题面附件 2 是出题组给定数据, **不修正**, 直接使用. **紧急购电数据 0 是附件 2 物理特性 + 0:00 用附件 2 当天实际 (隐含用了未来信息) 的合成结果** — 严格按 §2.6 用前一天实际预测, 紧急购电 = 基线 (万) kWh (94% 天).
> 若按真实气象 (含阴雨), 应有显著紧急购电, Q3 用附件 3 预报 + 滚动调整应**压缩**紧急购电.
```

**反模式** (踩过的坑):
1. ❌ 附件 2 全年无阴雨 → 人造梅雨季 50% 阴雨 ("数据修正") — 造假, 评阅扣分
2. ❌ 缩 g 上界让紧急购电触发 ("物理不严谨的紧急购电") — 题面没要求, 评阅不认
3. ❌ 报"数据有 bug, 模型跑不通" — 数据是题面给的, 模型跑不通 = **模型错**, 不是数据错

dryrun check 23: 扫 .py 看是否有 "人造数据 / 缩 g / 加噪声" 等物理造假关键词, yellow 警告.

## 8. 给跑题用户的 1 个核心问题

跑完每个问题, **自问 1 句**:

> "**这个问题的结果符合题目设计意图吗?** 如果不符合, **改方法** 或**改假设**, 不能接受'现实如此'."

这是 skill 测试的核心 — **跑通 ≠ 解对**, **解对 = 期望命中 + 方法合理 + 数据隔离 + 三口径正确 + 数据物理真实标注**.
