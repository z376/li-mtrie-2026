# 共享模块导入规范

> 适用：多问题共享的物理/数学/工具模块（如 `求解/共享/螺线.py`）

## 0. 为什么需要规范

**踩坑教训**：2024 国赛 A 题测试时，问题 4 用了 `arc_length` 但只 import 了 `xy_of_theta`，
运行报 `NameError`，浪费 5 分钟排查。

**问题根源**：
- `from 共享 import *` 太宽，污染命名空间
- `from 共享 import a, b` 容易漏写
- 没有规范，新问题代码不知该用哪种

## 1. 三种导入方式对比

| 方式 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| `from 共享 import a, b, c` | 显式，IDE 跳转友好 | 易漏写 | ⭐⭐⭐⭐ |
| `from 共享 import *` | 一次全导入 | 命名空间污染；不知道导入了什么 | ⭐ |
| `import 共享; 共享.a()` | 命名空间清晰 | 每次调用都加 `共享.` | ⭐⭐⭐ |

**推荐**：**方式 1（显式列全函数）**

## 2. 规范写法

```python
# 在每个问题代码顶部
import os, sys
sys.path.insert(0, os.path.join(os.path.dirname(__file__), '..', '共享'))

# ⭐ 显式列出本文件用到的所有函数（按字母序）
from 螺线 import (
    L_HEAD,           # 物理常量
    L_BODY,
    D_HANDLE,
    N_SECTIONS,
    arc_length,       # 几何函数
    xy_of_theta,
    tangent_vector,
)
```

**好处**：
- 漏一个会立即报 `ImportError` 或 `NameError`（不是运行时才报）
- IDE 跳转 `arc_length` 直接到定义
- 看到 import 段就知道本文件依赖什么

## 3. 共享模块的设计原则

放在 `求解/共享/` 下，**单文件 ≤ 300 行**，**单一职责**：
- `螺线.py` — 螺线几何（5 个问题共用）
- `动力学.py` — 刚体运动学（如适用）
- `优化工具.py` — 通用 scipy 优化封装
- `数据预处理.py` — 数据清洗/插补

如果共享模块超过 300 行，**按职责拆分**到多个文件。

## 4. 导入路径技巧

```python
# 当前文件: 求解/问题1/问题1_xxx.py
# 共享模块: 求解/共享/螺线.py
# 相对路径: ../../共享/

# 方法 A: 用相对路径（推荐，移植性好）
sys.path.insert(0, os.path.join(os.path.dirname(__file__), '..', '共享'))

# 方法 B: 用绝对路径（不推荐，依赖工作区）
# sys.path.insert(0, r'D:\project\求解\共享')
```

## 5. 验证清单

每写完一个 `from 共享 import (...)`，跑一次：

```python
# 验证导入成功的所有符号都在本地命名空间
from 螺线 import arc_length, xy_of_theta  # 按你列的
import sys
expected = ['arc_length', 'xy_of_theta']
for name in expected:
    assert name in dir(), f"导入失败: {name}"
print("✅ 所有共享符号导入成功")
```

## 6. 踩过的坑（案例库）

| 坑 | 症状 | 修复 |
|---|------|------|
| `from 螺线 import *` | 后续 `r` 不知道是本地还是导入的变量 | 改显式列全 |
| 只导入了一个函数但用了 3 个 | 运行时报 `NameError: name 'xxx' is not defined` | 显式列全后立即能发现 |
| 共享模块文件改了名 | 旧 import 报 `ModuleNotFoundError` | 改名前用 `grep` 找所有 import 引用 |
| 共享模块和当前问题代码互相 import | 循环引用，启动崩溃 | 共享模块**只能被**问题代码 import，反向不行 |

## 7. 复制粘贴模板

新写一个问题代码时，**复制下面这一段**到顶部：

```python
# ==================== 共享模块导入 ====================
import os, sys
# 路径: 当前文件 -> ../共享/
sys.path.insert(0, os.path.join(os.path.dirname(__file__), '..', '共享'))
# 👇 列出本文件用到的所有共享符号
from 螺线 import (
    # 常量
    # L_HEAD, L_BODY, D_HANDLE, N_SECTIONS,
    # 函数
    # arc_length, xy_of_theta, tangent_vector,
)
```

## 8. 跨问题常量统一定义（防止 PITCH=0.55 / pitch=0.5240 三个名字指一个量）

**踩坑教训**：2024 A 题测试时——
- 问题 1 估出螺距 `PITCH = 0.55`
- 问题 3 又用 `pitch = 0.5240`（独立变量）
- 问题 4 又用 `p = 0.55`（拷贝粘贴）

三个名字指代同一个物理量，论文里符号说明表也对不上。**评审立刻标"模型不严谨"**。

**规范**：

### 8.1 物理常量 → `求解/共享/constants.py`

所有"全篇都用到、值不变的物理量"放这里，**只用大写下划线命名**：

```python
# 求解/共享/constants.py
# 全篇统一物理常量（只在这里定义，其他文件 from 导入）
PITCH = 0.55              # 螺距 (m)
L_HEAD = 3.41             # 龙头板长 (m)
L_BODY = 2.20             # 龙身板长 (m)
D_HANDLE = 0.275          # 把手到板头距离 (m)
W_BOARD = 0.30            # 板宽 (m) — 碰撞距离阈值
G = 9.81                  # 重力加速度 (m/s^2)
```

### 8.2 跨问题参数（求解过程中估出、后续还要用）→ `求解/共享/params.py`

```python
# 求解/共享/params.py
# 跨问题参数（求解后估出，下游问题 import 复用）
P_MIN = 0.5240            # 最小螺距 (m) — 问题3 估出,问题4 复用
T_COLLISION = 443         # 终止时刻 (s) — 问题2 估出,问题5 复用
R_TURN_INNER = 0.5        # 调头内弧半径 (m) — 问题4 估出
```

### 8.3 跨问题参数使用流程

```
问题1: 估 PITCH = 0.55       → 写入 共享/constants.py
问题2: 用 PITCH (从共享 import) → 不重定义
问题3: 二分估 P_MIN = 0.5240  → 写入 共享/params.py
问题4: 用 PITCH + P_MIN       → 全部 from 共享 import
问题5: 用 T_COLLISION         → from 共享 import
```

**门控检查**（Step 2.Gate 必跑）：每写完一个问题，反问 3 条：
1. 本问的物理常量（p/L/d 等）**是否在共享 constants.py 已定义**？没就新建
2. 本问的"前问输出"参数（如 p_min / t_collision）**是否在共享 params.py 已记录**？
3. 本问的变量名是否跟其他问题**命名一致**？（`PITCH` 不要写成 `pitch` / `p`）

### 8.4 反例（不要这么写）

```python
# ❌ 问题1_xxx.py 顶部
PITCH = 0.55
L_HEAD = 3.41

# ❌ 问题3_xxx.py 顶部
pitch = 0.5240  # 同一个量，不同名字，不同值
P = 0.55        # 第三个名字
```

→ 三个文件搜 PITCH / pitch / p 你能搜出 3 个不同的"螺距"，出问题不知道是哪个。
