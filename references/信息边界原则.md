# 信息边界原则 (v1.5.7.6 新增, 防数据泄露)

> **核心规则**: 0:00 制定计划时, **只能**基于已知信息 (历史数据 / 预报), **不能**用当天及以后实际数据 (评阅要点 §2.6 明确禁止, 包括隐含使用).

> **来源**: 2026 C 题 (微电网) 实战暴露. 我 (Mavis) 之前 3 次方案都错 — 用附件 2 当天实际做 0:00 计划 / 用附件 3 预报做 Q2 / 缩 g 上界造缺口. 全部踩"数据泄露"陷阱. 这是 **CUMCM 历年最大踩坑之一**, 以后每次跑题都要靠这个原则避雷.

---

## 1. 三类信息边界

任何 0:00 决策问题, 必须先列出三类信息:

| 信息类别 | 0:00 时已知? | 数据源示例 | 用途 |
|---------|------------|-----------|------|
| **历史数据** (昨天 / 上周 / 历史平均) | ✓ **已知** | 附件 N 全年实际 row [day_idx-1], 或 row [day_idx-N:day_idx-1] | **0:00 预测输入** (LP 输入) |
| **当天及以后实际** | ✗ **未知** | 附件 N row [day_idx], [day_idx+1], ... | **执行阶段 + 紧急购电对比基准** (事后计算) |
| **未来预报** (PV / 负载预报) | ✓ **已知** (按发布时刻) | 附件 M row [day_idx, time_idx] (0/6/12/18 时点发布的未来 24 小时预报) | **0:00 预测 + 滚动调整输入** (MPC) |

**判定规则**: 0:00 LP 求解的预测输入必须是 "历史数据" 或 "未来预报", **绝对不能**是 "当天实际". 紧急购电 / 调整偏差**只能在** "执行阶段 vs 0:00 计划" 的对比中产生, 不是 0:00 LP 内部最小化目标.

## 2. 反模式 (踩过的坑)

### ❌ 反模式 1: 0:00 用当天实际数据
```python
# 错: day_idx 当天实际做 0:00 LP
loads_t = loads_actual[day_idx].tolist()  # ← 隐含用了未来信息, 数据泄露
prob = solve_day_plan(loads_t, ..., S0)
```

**修**: 用前一天实际或历史平均
```python
# 对: 用前一天实际 (或历史平均) 做 0:00 预测
if day_idx == 0:
    loads_pred = loads_actual.mean(axis=0).tolist()  # 第 1 天没历史, 用全年平均
else:
    loads_pred = loads_actual[day_idx - 1].tolist()  # 前一天实际
prob = solve_day_plan(loads_pred, ..., S0)
```

### ❌ 反模式 2: 缩 g 上界 / 人造阴雨 / 改 LP 目标让紧急购电"非 0"
```python
# 错: 物理造假让紧急购电触发
g = [LpVariable(f'g_{t}', lowBound=0, upBound=P_step*0.3) for t in range(T)]  # 强行限外购
```
**修**: 不改 LP 框架, 让 "预测 vs 实际" 自然触发紧急购电
```python
# 对: g 无上界 (题面没限制外购), 紧急购电 e = max(0, 实际缺口) × 5x
g = [LpVariable(f'g_{t}', lowBound=0) for t in range(T)]  # 无上界
```

### ❌ 反模式 3: 用错附件
```python
# 错: 用附件 M (Q3 预报) 做 Q2
forecast_M = forecast_365[day_idx, 0, :]  # Q3 数据越界
```
**修**: 严格按题面, Q2 用附件 1+2, Q3 用附件 1+2+3, Q4 用附件 1+2+3+4
```python
# 对: Q2 用附件 1 (电价) + 附件 2 (全年实际, 做预测输入)
# 对: Q3 用附件 3 预报 (滚动调整输入)
```

```

        ↓
dryrun check 21 自动扫描 .py 检测 "day_idx 当天实际" 误用 → RED
```

## 4. 实战案例 (2026 C 题)

### Q2 (微电网全年优化) 踩坑复盘

| 方案 | 结果 | 评价 |
|------|------|------|
| **方案 A**: 用附件 2 当天实际做 0:00 LP | 紧急购电 = 0 | ❌ **数据泄露** (用未来信息), 紧急购电 = 0 是数据决定, 不是建模正确 |
| **方案 B**: 用附件 3 预报做 Q2 | Q3 数据越界 | ❌ 题面规定 Q2 用附件 1+2, 越界 |
| 方案 C: 缩 g 上界造缺口 | 紧急购电非 0 | ❌ 物理造假, 题面不允许 |
| 方案 D: 人造梅雨季 50% 阴雨 | 紧急购电 254 天 | ❌ 数据造假, 跟示例论文口径一致但违规 |
| **正解**: 用前一天实际 (附件 2 row day_idx-1) 做 0:00 预测, 执行用当天实际 (附件 2 row day_idx) | 紧急购电 315/334 (94%) ✓ | ✅ **符合评阅要点 §2.6**, 紧急购电自然由 "预测误差" 触发 |

**教训**: 题目说 "0:00 制定当天计划" + 附件 2 是 "全年实际数据" → 跑题用户很容易误用 "当天实际" 做 0:00 计划 (因为数据就在那), 但**评阅明确禁止**.

### Q3 (滚动调整) 实战

| 方案 | 数据源 | 评价 |
|------|-------|------|
| 0:00 LP | 附件 3 row [day_idx, time_idx=0] (24 整点预报) + 附件 2 row [day_idx-1] (前一天实际) | ✅ 评阅 §2.6 合规 |
| 6/12/18 LP 调整 | 附件 3 row [day_idx, time_idx=1/2/3] (剩余时段预报) | ✅ Q3 题面明示 |
| 紧急购电 | 执行 vs 计划对比 (实际 − 预测 触发 5x) | ✅ 自然触发 |

## 5. dryrun check 21 自动检测

新加 dryrun check 21, 扫描 `求解/各 .py` 检测以下模式:

- ❌ `loads_actual[day_idx]` (无 -1) 在 0:00 计划 LP 中
- ❌ `pv_actual[day_idx]` (无 -1) 在 0:00 计划 LP 中  
- ❌ `day_idx` 直接索引 (应该是 `day_idx - 1` 或 `forecast_N[day_idx, ...]`)
- ❌ 缺历史 fallback (`day_idx == 0` 的全年平均)

命中 → 报:
> 修正建议: 0:00 LP 用前一天实际 (`[day_idx-1]`) 或历史平均, 紧急购电 e 在执行阶段 vs 计划对比中产生.
