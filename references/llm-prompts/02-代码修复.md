# LLM 工具 02：代码自动修复（96 小时救星）

> 学生自用，给 Mavis / Claude / GPT 调用的**结构化 prompt 模板**。把 traceback + 代码片段喂给 LLM，让它给你**根因 + 最小修复 + 验证步骤**。
>
> **价值**：96 小时里 30% 都在 debug，本工具节约 8-10 小时。

---

## 何时用

- `python xxx.py` 报 traceback
- matplotlib 出图空白 / 报错
- LaTeX 编译 `! Error` / `Undefined control sequence`
- pandas 数据读取乱码 / 缺失
- 任何"代码跑不通但不知道为啥"的场景

不替代 stackoverflow 搜索，而**加速你 debug**：LLM 看 50 行代码比人快，定位根因比 trial-and-error 快。

---

## 使用方法

1. 打开 Mavis / Claude / GPT 会话
2. 复制下方"📋 Prompt 模板"段
3. 替换 4 个占位符（traceback + 代码 + 已尝试 + 输出格式）
4. **重要**：把 LLM 建议的 fix **先在备份上试**，跑通后再覆盖原文件
5. 跑 `references/scripts/aigc_scan.py` + `verify_pdf_metrics.py` 自检

**预期时间**：5-15 分钟 / 1 个 bug（vs 1-2 小时 trial-and-error）

## 📋 Prompt 模板

```
你是 Python 调试专家。下面给你一个 traceback 和相关代码片段。请按 OUTPUT_FORMAT 严格输出。

# Traceback（完整复制）
```
{TRACEBACK}
```

# 报错代码（最小复现版本，删掉无关 import）
```python
{CODE}
```

# 运行环境
- Python 3.10+
- 平台: {Windows 11 / Linux / WSL}
- 关键包: pandas 2.x, numpy 1.24+, matplotlib 3.7+, scipy 1.11+

# 我已尝试（避免重复建议）
- {已尝试的修复 1}
- {已尝试的修复 2}

# OUTPUT_FORMAT（严格 JSON，不要解释）

{
  "root_cause": "根因（一句话，不超过 30 字）",
  "mechanism": "为什么触发这个错误（不超过 100 字）",
  "minimal_fix": {
    "before": "原代码片段（3-10 行）",
    "after": "修复后代码片段（3-10 行）",
    "diff_explanation": "改了什么 + 为什么（不超过 50 字）"
  },
  "alternative_fixes": [
    {"approach": "另一种思路（适用于 X 场景）", "code": "代码片段"}
  ],
  "verification_steps": [
    "跑 X 命令应得 Y 结果",
    "如不通过则 Z"
  ],
  "prevention": "未来怎么避免这个错误（一条规则）"
}

# 严禁
- 不要建议"重装包""重启 Python""换 IDE"等逃避性回答
- 不要修改 traceback 没提到的代码（先定位到根因）
- 不要建议换算法（除非根因就是算法不适用）
- 不要给未经 traceback 验证的修复
```

## 输出示例（节选）

```json
{
  "root_cause": "DataFrame merge 键类型不匹配（int64 vs object）",
  "mechanism": "pandas 自动推断 '001' 为 object，但原始 df['id'] 为 int64，merge 时对齐失败导致空 DataFrame，后续 groupby 报 KeyError",
  "minimal_fix": {

  },
  "verification_steps": [
    "print(df.shape)  应是 (N, M) 不是 (0, M)",
    "print(df.dtypes)  确认 id 是 object"
  ],
  "prevention": "merge 前先 assert df1['id'].dtype == df2['id'].dtype"
}
```

## 反例 / 警示

**LLM 改完不一定对**。3 道防线：
1. **diff 必读**：LLM 输出的 fix_diff 至少 30 秒看一遍
2. **测试必跑**：LLM 给的 verification_steps 逐条跑
3. **备份必留**：fix 前 `cp xxx.py xxx.py.bak`，fix 后 `rm xxx.py.bak`

如果 LLM 建议"重装 X 包"或"换版本"——**直接忽略**，根因没找到。

---

## 自检

跑完 1 轮 LLM 代码修复后，对照以下 5 条：

- [ ] root_cause 一句话能说清（不是"可能是..."模糊）
- [ ] minimal_fix 的 diff 不超过 10 行（改多了说明没找对根因）
- [ ] 跑完 verification_steps 全部通过
- [ ] 没改 traceback 之外的代码
- [ ] 没引入新的 print/debug 噪音（LLM 喜欢加 print 调试）

## 批量用法

如果同时有多个报错，按**根因优先级**排序喂给 LLM：
1. **ImportError / ModuleNotFoundError**（最优先，1 行 pip 解决）
2. **SyntaxError**（LLM 改字符串就够）
3. **TypeError / AttributeError**（根因明确，LLM 擅长）
4. **ValueError**（数据问题，可能 LLM 也找不准）
5. **RuntimeWarning / FutureWarning**（不阻塞，先放着）

1 个 session 处理 1 个 bug，**不要 1 个 session 处理 5 个 bug**（上下文会乱）。
