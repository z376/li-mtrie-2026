# references/llm-prompts/ — LLM 工具集成（v1.4.5 起）

> **学生自用**的 LLM 工具集。把结构化 prompt 喂给 Mavis / Claude / GPT，让它**结构化输出**（JSON），避免 LLM"泛泛而谈"或"政治正确建议"。
>
> **不调外部 API**，不烧 token。**复制粘贴**到任何 LLM 会话即可。

---

## 3 个工具

| # | 工具 | 何时用 | 预期时间 | 价值 |
|---|------|--------|----------|------|
| **01** | [选题推荐](01-选题推荐.md) | 读完题不确定问题类型 | 5 分钟 | 中（替代手填 4 列表） |
| **02** | [代码修复](02-代码修复.md) | `python xxx.py` 报 traceback | 5-15 分钟 | **高**（96 小时里 30% 在 debug） |
| **03** | [自动审稿](03-自动审稿.md) | 写完 1 章 / 终审前 | 10-20 分钟 | 中（终审前提前自审） |

---

## 核心原则

- **不调外部 API**：学生 copy-paste prompt 到 Mavis / Claude / GPT 即可
- **结构化 JSON 输出**：避免 LLM 泛泛而谈，强制结构化字段
- **5 维评分（工具 03）**：机理 / 数据 / 写作 / 创新 / 排版
- **三道防线（工具 02）**：diff 必读 / 测试必跑 / 备份必留

---

## 与现有 references 的协同

- **工具 01 选题推荐** ↔ `references/模型决策树.md` + `references/整题建模模式.md` + `workflow.md §1.5 4 段式分析`
- **工具 02 代码修复** ↔ `references/scripts/data_utils.py` (utf-8-sig) + `references/去AIGC指南.md §5` (AI 当审稿人)
- **工具 03 自动审稿** ↔ `references/国奖级硬性指标.md §3 26 条自查表` + `references/验收清单.md 38+ 项` + `references/题意红线.md`

## 使用流程

```
T+0h    读题 → 工具 01 选题推荐 → 写入 求解/求解计划.md
T+24h   写完 §5 → 工具 03 自动审稿（第 1 轮，focus 机理 + 创新）
T+72h   写完 §6-7 → 工具 03 自动审稿（第 2 轮，focus 数据 + 写作）
T+72h   debug 高峰 → 工具 02 代码修复（按 ImportError → SyntaxError → TypeError 优先级）
T+90h   终稿 → 工具 03 自动审稿（第 3 轮，focus 写作 + 排版）
T+92h   喂工具 03 输出的 example_phrases_to_replace → §AIGC 降重
T+96h   提交
```

## 严禁清单（所有工具通用）

- ❌ 让 LLM 编造数据 / 文献 / 数字（违反 2026 AI 规定第 4 条）
- ❌ 让 LLM 替你拍板（必须团队讨论 + 对照参考论文 + 跑通代码）
- ❌ 把 LLM 输出原封不动贴进论文（必须自审 + 改写 + 跑 AIGC 扫描）
- ❌ 1 个 session 处理 5+ 个 bug（上下文会乱，1 session 1 bug）
- ❌ 用工具 02 让 LLM 改出 "政治正确" 答案（违反 §5 红旗第 1 条: 不编内容）

---

## 何时**不要**用 LLM 工具

- 选题在题组判定上（A/B/C/D/E 错选 = 0 分）—— 自己看 `SKILL.md §Step 0`
- 算最终提交前最后 1 小时（时间不够自审 LLM 输出）
- 替代 `references/去AIGC指南.md §5` 改写（要先用 LLM 指出问题，再人工改，最后用 LLM 验证）
